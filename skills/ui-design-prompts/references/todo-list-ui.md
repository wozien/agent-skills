# Todo List UI

- **id:** `todo-list-ui`
- **别名:** 待办列表 UI, 任务管理界面, Todo 设计系统, 清单应用
- **一句话:** 柔和卡片。优先级一目了然。点一下就能往前推进。
- **适用:**
  - 待办清单与任务管理应用
  - 更大产品中的清单功能（入职、项目、CRM）
  - 习惯打卡与个人计划工具
  - 带优先级与状态的团队任务列表
  - 以行展示记录并带快捷操作的管理后台
  - 需要精致 CRUD 示例的学习项目与作品集应用
- **避免:**
  - 10 列及以上的稠密数据表（改用紧凑表格系统）
  - 以看板为主、跨列拖拽是核心交互的产品
  - 需要中性、严肃气质的企业工具
  - 深色、高对比的开发者工具
- **来源:** https://uidesignprompts.com/prompts/todo-list-ui

## Prompt

## 待办列表 UI — 设计系统

### 你在构建什么
一个待办清单或任务管理器：每条任务都是一张浮起的白色行卡片，整个界面轻盈、圆润、友好。用户只做四件事：
1. 扫视 — 阅读任务列表，一眼看到优先级与状态。
2. 推进 — 点击状态标签（待办、进行中或已完成），把任务往前移，并更新进度环。
3. 新增或编辑 — 使用柔和、大圆角的模态表单。
4. 删除 — 在简短、居中的对话框中确认。

视觉任务是让长列表显得平静。没有边框、没有表格线、没有厚重的外壳。行卡片浮在带一点冷蓝的灰白画布上，阴影几乎察觉不到；颜色只出现在有意义的地方：优先级、状态，以及唯一的紫色操作色。

用户自行提供产品名、文案和数据模型。按本提示搭建结构、间距与行为，并把示例文字（“Lorem Ipsum”、“Todo(s)”）替换成真实内容。

### 视觉识别 — 柔和生产力
- 画布是带一点蓝的冷灰白，纯白行卡片和模态才能从中浮起。
- 行卡片与模态为白色，圆角非常大（24px 到 32px），阴影非常柔。
- 紫色是唯一品牌色。出现在主按钮、进度环、焦点态和选中控件上。它始终带有柔和的紫色光晕阴影。
- 优先级与状态使用各自的小色系（绿、琥珀、红；灰、蓝、薄荷绿）。它们从不使用紫色，这样紫色永远表示“行动”。
- 字体圆润温暖。标题粗重；标签小、灰、安静。
- 图标为描边风格，22px，2px 描边，圆线帽与圆转角。

### 字体排印
只用一个字体家族：Nunito（字重 400、600、700、800）。回退：Nunito Sans、Quicksand、system-ui。
Nunito 的圆端点对柔和气质至关重要；不要换成几何或 grotesk 无衬线。
```
页面标题：      40px   字重 800   lh 1.1    颜色 --ink     (“Todo(s)”)
模态标题：      26px   字重 800   lh 1.2    颜色 --ink
对话框文字：    22px   字重 600   lh 1.4    颜色 --ink     居中
行内数值：      18px   字重 600   lh 1.3    颜色 --ink
行内标签：      14px   字重 500   lh 1.3    颜色 --label
字段标签：      16px   字重 700   lh 1.3    颜色 #7C8196
输入文字：      17px   字重 500   颜色 --ink     占位符 --label
按钮：          17px   字重 700
优先级文字：    15px   字重 700
徽章 / 芯片：   13px   字重 700   letter-spacing 0.01em
说明 / 计数：   14px   字重 500   颜色 --label
```
计数和日期使用等宽数字。行内标题不超过两行（限制 2 行，第二行省略号）。

- 内容栏：`max-width: 760px`，在平板和手机上居中；宽桌面上可居中或靠左并留充足左边距，但永不拉宽超过 760px。
- 页面内边距：桌面顶部 48px、两侧 32px；移动端顶部 24px、两侧 16px。
- 页头行：左侧页面标题，右侧主按钮「添加待办」，垂直居中，其下 32px 开始列表。
- 页头与列表之间可选控制行（筛选、搜索、排序）：高 56px，页头下方 20px，列表上方 20px。见扩展。
- 行间距：16px。列表底部内边距：96px（给 toast 和移动端浮动按钮留空间）。

### 待办行（核心组件）
每条任务是一张浮起的白色卡片，五列网格。
```
┌───────────────────────────────────────────────────────────────────────────┐
│ 待办           优先级         ┌────────┐     ( )        [编辑] [删除]   │
│ Lorem Ipsum    ↓ 低           │ 待办   │   进度环                        │
└───────────────────────────────────────────────────────────────────────────┘
   1fr (标题)     140px (居中)   120px        44px          88px
```
```css
.todo-row {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 140px 120px 44px 88px;
  align-items: center; column-gap: 16px;
  min-height: 90px; padding: 0 28px;
  background: var(--surface); border-radius: 26px; box-shadow: var(--shadow-row);
  transition: transform .2s ease, box-shadow .2s ease;
}
.todo-row:hover { transform: translateY(-2px); box-shadow: 0 14px 36px rgba(31,41,90,0.09); }
```
列细节：
1. 标题：小灰标签「待办」（14px，`--label`）在任务名上方（18px，600，`--ink`）。
   每行都重复该标签，让每张卡片自解释。长名称限制 2 行。
2. 优先级：小灰标签「优先级」居中，下方是箭头图标加优先级词，成对居中：
   - 高：向上箭头，红色 `#FF3B4E`，文字「高」
   - 中：向上箭头，琥珀 `#FDB821`，文字「中」
   - 低：向下箭头，绿色 `#19C85A`，文字「低」
   箭头 20px，2.4px 描边，圆线帽。文字 15px，字重 700。箭头和文字都带颜色，方向加文字意味着颜色不是唯一信号。
3. 状态标签按钮：可点击药丸，圆角 10px，padding 7px 14px，13px 字重 700，
   最小 44px 触控目标。使用真正的 `<button type="button">`，不是静态标签。
   点击循环 待办 → 进行中 → 已完成 → 待办。标签立即更新，同时进度环在 900ms 内缓慢填满或清空到新值。
   - 待办：背景 `#EDEEF2`，文字 `#7B8094`
   - 进行中：背景 `#E5F0FF`，文字 `#3D8BFD`
   - 已完成：背景 `#DDF7EC`，文字 `#12B886`
4. 进度环：28px 圆，与状态标签同步：待办为空（0 percent），
   进行中半满（50 percent），已完成全满（100 percent）。
   进度环也可点击，用与标签相同的行为循环状态。
5. 操作：两个 40px 图标按钮，间距 8px，右对齐：
   - 编辑：描边铅笔方框图标，22px，`--ink`。
   - 删除：描边垃圾桶图标，22px，`--danger`（`#FF5C6C`）。
   按钮静止时无背景；悬停时背后出现 `--fill-soft` 圆（40px，圆角 12px），图标缩放到 1.08。

已完成行保持全彩和全对比。不要给整行加删除线或淡化；进度环和绿色已完成徽章已足够。可选：仅当产品明确需要「勾掉」外观时，标题可加 1px、60 percent 不透明度的删除线。

### 可点击状态标签与进度环
状态标签是主要状态控件。点击或在其上按 Enter 或 Space 会循环
待办 → 进行中 → 已完成 → 待办。可见标签文案、标签颜色和进度环一起更新，且变更被持久化。进度环点击也支持同样循环。
```html
<button class="ring" aria-label="状态：进行中。按键可更改。">
  <svg viewBox="0 0 28 28" width="28" height="28" fill="none">
    <circle cx="14" cy="14" r="11" stroke="#E3E5EC" stroke-width="2.5"/>
    <circle class="arc" cx="14" cy="14" r="11" stroke="#6C3CFF" stroke-width="2.5"
            stroke-linecap="round" stroke-dasharray="69.1" stroke-dashoffset="34.55"
            transform="rotate(-90 14 14)"/>
  </svg>
</button>
```
周长约为 69.1（r = 11）。状态：
- 待办：仅灰色环，弧上 `stroke-dashoffset: 69.1`（弧隐藏）。
- 进行中：紫色弧正好覆盖一半，50 percent（`stroke-dashoffset: 34.55`）。
- 已完成：紫色弧覆盖 100 percent（`stroke-dashoffset: 0`）。中心可淡入一个白底紫的小对勾以增强清晰度（可选，12px）。
用 `cubic-bezier(.4,0,.2,1)` 在 900ms 内动画 `stroke-dashoffset`，让进度缓慢可见地从空到半、从半到满，或清空回零。绝不要直接跳到目标值。从当前显示的弧开始，包括快速连点时，并在渲染更新后的行时保留该动画，而不是换成已经处于终值的环。状态徽章文字和颜色在 200ms 内更新，同时环继续填充。悬停环缩放到 1.1。
标签和环都是真正的 `<button>`，最小命中区域 44px。两者都宣告当前状态和下一个状态。更改状态后，焦点留在被激活的控件上；若筛选隐藏了更新后的任务，则把焦点移到当前筛选上。

### 模态
所有模态使用同一遮罩：`background: var(--overlay)` 配 `backdrop-filter: blur(4px)`，
内容居中，打开时 220ms 淡入加 12px 上移。Escape 和点击遮罩关闭。
焦点被困住，关闭时回到触发器。背后页面停止滚动。

#### 新增 / 编辑待办模态
```

│  待办名称                                    │
│  ( Lorem Ipsum                         )     │
│                                              │
│  难度                                        │
│  [ 难 ]  ( 中 )  ( 易 )                      │
│                                              │
│  优先级                                      │
│  ( 高                                v )     │
│                                              │
│                                   [  添加  ]  │
└──────────────────────────────────────────────┘
```
- 尺寸：宽 600px（最大 92vw），最小高度 560px，padding 40px 48px，白底，
  圆角 32px，阴影 `--shadow-modal`。
- 标题：「添加待办」（或「编辑待办」），26px 字重 800，左上。
- 关闭按钮：右上，52px 方形，圆角 16px，背景 `--fill-soft`，X 图标 22px，
  2.4px 描边，颜色 `--ink`。悬停：背景 `#EBEEF5`，X 旋转 90 degrees。
  `aria-label="关闭"`。
- 字段组间距 28px。字段标签：16px 字重 700，`#7C8196`，控件上方 10px。
- 文本输入：高 58px，padding 0 22px，圆角 18px，边框 1.5px `--line`，白填充，

  配 ring `0 0 0 4px rgba(255,59,78,0.12)` 以及行内提示（见下）。
- 难度芯片：一行三个，间距 12px。
  ```css
  .chip { height: 40px; padding: 0 24px; border-radius: 12px; font-weight: 700; font-size: 14px;
          background: #fff; border: 1.5px solid var(--c); color: var(--c);
          transition: background .15s, color .15s, transform .15s; }
  .chip[aria-pressed="true"] { background: var(--c); color: #fff; }
  .chip:hover { transform: translateY(-1px); }
  /* --c: 难 #FA3449, 中 #FDC84A, 易 #00CF98 */
  ```
  同一时间只选一个难度（单选行为，用带 `aria-pressed` 的按钮实现，放在 `role="radiogroup"` 内）。未选芯片用自身颜色描边和彩色文字；选中芯片实心填充白字。对比度例外：中等芯片未选时文字用 `#B88400`，选中时填充 `#FDC84A`、文字用海军蓝 `--ink`，因为白字配琥珀对比不足。
- 优先级选择：同样 58px 字段样式，左侧值文字，右侧向下 chevron 图标（20px，
  `--ink`）。打开菜单（见下）。
- 主操作：「添加」（或「保存更改」）按钮锚定右下，高 58px，
  最小宽 170px，圆角 20px，紫色带光晕，18px 字重 700。禁用态（还没有名称）
  为 `#D9D2FF` 填充、白字、无光晕。
- 校验：名称必填。在字段下方显示 14px 红色提示加小警告图标
  （「给你的待办起个名字」），绝不能只有红边框。
- 名称字段按 Enter 在有效时提交。

#### 优先级选择菜单
在字段下方打开的自定义列表框：
- 白色面板，圆角 24px，padding 8px，阴影 `--shadow-menu`，宽度等于字段。
- 选项：高、中、低，各高 52px，padding 0 20px，18px 字重 500，`--ink`。
- 悬停与键盘焦点：背景 `#F6F4FF`。选中项：字重 700，右侧紫色对勾图标。
- 可选：每个词左侧显示彩色优先级箭头以强化含义。
- 以 150ms 淡入加 6px 滑动打开；选择、Escape 或点击外部关闭。
- 键盘：上/下移动，Enter 选择，Home 和 End 跳转，输入首字母跳转。
- ARIA：`role="listbox"`，选项为 `role="option"`，使用 `aria-activedescendant`。

#### 删除确认对话框
```
┌────────────────────────────────────┐
│                                    │
│     确定要删除                     │
│     这份清单吗？                   │
│                                    │
│     [ 删除 ]     ( 取消 )          │
│                                    │
└────────────────────────────────────┘
```
- 宽 520px（最大 92vw），padding 56px 48px 48px，白底，圆角 20px，阴影 `--shadow-modal`。
- 文案：22px，字重 600，`--ink`，居中，最大宽 320px，两行。尽可能引用条目
  （「删除『Lorem Ipsum』？」）但保持两行。
- 按钮：居中一行，间距 24px，各高 62px、宽 172px，圆角 18px。
  - 删除：紫色填充，白字，紫色光晕（主按钮样式）。这与设计一致：删除是被强调的操作。需要更强警告的产品可将这一颗按钮换成 `--danger` 填充和光晕，但保持同样尺寸与形状。

### 空态、加载与反馈
- 空态：在列表区域居中，96px 柔和紫晕圆配 `--primary` 清单描边图标，
  一行 22px 字重 800（「还没有待办」），一句 15px `--label`，以及主按钮「添加待办」。
- 加载：4 条骨架行，高度和圆角与真实行相同；色块 `#EEF0F8`，缓慢从左到右微光。
- Toast：新增、编辑、删除或状态变更后，深海军蓝药丸（`--ink`，白字 15px 字重 600，
  圆角 16px，padding 14px 22px）从底部中央滑上，停留 3 秒，可含 `#B9A6FF` 的「撤销」文字按钮。校验错误绝不用 toast。
- 新增动画：新行下滑 12px 并在 250ms 内淡入，平滑推开其他行。
- 删除动画：确认后行在 250ms 内收起（高度到 0，不透明度到 0）。

### 扩展（可选，保持同一视觉语言）
- 列表上方筛选标签：`--fill-soft` 轨道中的分段控件（圆角 16px，padding 4px），
  项为全部、待办、进行中、已完成；激活项为带 `--shadow-row` 的白色药丸和 `--ink` 文字；未激活项用 `--label`。
- 搜索：52px 输入，匹配字段样式，带搜索图标，放在标签右侧。
- 排序：小型选择（「优先级」「最新」「状态」），字段样式。
- 截止日期：标题下小日历图标加 `--label` 的「明天」；逾期用 `--prio-high`。
- 拖拽重排：悬停时行左缘出现 6 点把手；被拖行以 `--shadow-menu` 和 1.02 缩放抬起。
- 分组：13px 大写标签（「今天」「稍后」），`--label`，上 24px 下 12px。
- 计数：每个标签旁紫色淡底徽章显示条目数。

### 响应式行为
- 900px 及以上：按规范的五列行。
- 600 到 899px：行内边距减到 22px，优先级列减到 120px；保留所有列。
- 低于 600px：行变成两行卡片，高度自动，padding 18px 20px：
  - 第 1 行：标题（全宽，最多 2 行）和最右侧进度环。
  - 第 2 行：优先级、状态徽章和两个操作图标，一条 flex 行，space-between。
  - 移动端隐藏「待办」和「优先级」标签以省空间；箭头和徽章已自解释。
- 页头按钮变成 56px 圆形浮动操作按钮，固定右下（内缩 20px），
  带加号图标和紫色光晕；页头只保留标题。
- 低于 600px 的模态变成底部抽屉：全宽，仅上角圆角 32px，从底部滑上，
  顶部中央 40px × 5px 拖动手柄，添加按钮拉满全宽。
- 触控目标从不小于 44px × 44px。

### 动效
- 行悬停抬起：200ms。按钮悬停抬起：200ms。芯片抬起：150ms。
- 环进度：上述缓动的缓慢 900ms 填充/清空，外加 200ms 徽章交叉淡入。
- 模态：220ms 淡入上移；遮罩同步淡入。关闭：160ms。
- 列表变化（新增、删除、重排）在 250ms 内做布局动画。
- 尊重 `prefers-reduced-motion`：去掉抬起和旋转，保留不透明度淡入和环状态变化但不做动画。
- 默认没有任何弹跳、摇摆或五彩纸屑庆祝。

### 无障碍
- 列表是带 `<li>` 行的 `<ul>`。每行的无障碍名称来自任务标题。
- 优先级由箭头、词语和颜色共同传达。状态由徽章文字和环共同传达。
- 状态标签和环按钮宣告当前状态以及激活结果
  （「状态：待办。按下可标为进行中。」），并更新 `aria-live="polite"` 区域。
- 图标按钮有 `aria-label`（「编辑 Lorem Ipsum」「删除 Lorem Ipsum」）。
- 模态：`role="dialog"`，`aria-modal="true"`，由标题标注，焦点困住，Escape 关闭，
  焦点回到触发器。删除对话框使用 `role="alertdialog"`。
- 可见焦点：每个可交互元素 `outline: 3px solid rgba(108,60,255,0.45); outline-offset: 3px;`。
- 文字对比：海军蓝配白通过 AAA；`--label` 灰 `#8A8FA3` 仅用于非必要标签，
  任何必要信息使用 `--ink-soft` 或 `--ink`。白底上的琥珀优先级文字 `#FDB821` 大且粗，
  但仍应检查；若产品需要 AA，加深到 `#D99A00`。
- 不要依赖悬停；触控设备上所有操作在静止时都可见。

### 数据模型
```
id:         string
title:      string          // 必填，最多 120 个字符
level:      "hard" | "medium" | "easy"        // 投入，可选（默认 medium）
priority:   "high" | "medium" | "low"         // 重要程度（默认 medium）
status:     "todo" | "in-progress" | "done"   // 默认 todo
due:        ISO date | null                    // 可选
notes:      string | null                      // 可选
createdAt:  ISO datetime
order:      number
```
难度和优先级有意不同：难度是任务有多难，优先级是有多紧急。列表显示优先级和状态；难度出现在新增和编辑表单中，需要时也可作为行上的小色点。
演示用 localStorage 持久化；真实产品使用 API 和乐观更新。

### 内容槽位（由用户提供）
- `[PAGE_TITLE]` 和可选副标题
- `[TASK_NOUN]` 用于文案（「待办」「任务」「清单项」），出现在按钮、模态标题和对话框中
- 初始示例任务（6 到 8 条真实条目，覆盖所有优先级和状态）
- `[PRIORITY_LABELS]` 和 `[LEVEL_LABELS]`（若产品要改名）
- 空态句子和 toast 文案

### 不要做
- 行之间没有边框或分隔线；行只靠阴影浮起。
- 没有表头、斑马纹或网格线。
- 没有尖角；本系统中没有任何东西圆角小于 10px。
- 没有纯黑文字，没有冷灰文字；使用海军蓝和标签灰。
- 没有第二种品牌色；紫色是唯一操作色。
- 优先级或状态指示器上不用紫色。
- 整行不为优先级上色（箭头和文字承载含义）。
- 不以带勾的复选框作为主要状态控件；可点击状态标签是主控件，
  同步的进度环也支持状态循环。
- 图标不用实心填色；保持圆线帽与圆转角的描边图标。
- 没有硬黑投影；阴影带海军蓝或紫色调且非常柔。
- 桌面模态不小于指定宽度，且模态必须有关闭入口。
- 除非产品明确覆盖对话框，否则删除按钮不用红色；默认是紫色。
- 完成或更改状态不弹出确认；只有删除才询问。
- 上线产品中不留下占位「Lorem Ipsum」。
